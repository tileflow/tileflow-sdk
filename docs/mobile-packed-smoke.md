# Packed mobile consumer smoke

These opt-in contributor checks compile fresh consumers from this checkout's packed artifacts.
They are not part of `check`, `verify`, Required checks or a publication workflow. No command
launches an application, renders a map, contacts Hosted, publishes packages or establishes product
availability. The direct manifest URL in the minimal application is an intentionally unreachable
`https://example.invalid/...` placeholder; compilation does not fetch it.

## Prerequisites

Use Linux or macOS, Node.js 22 or newer, npm, `tar`, and exactly the pnpm version in the root
`package.json`. Provision these tools before running the check. Corepack network provisioning is
disabled by the smoke. Public npm, Gradle/Maven and Apple/CocoaPods/SPM downloads used by the
selected mode must be reachable; no private registry credentials are read.

Android additionally requires an explicit `JAVA_HOME` for JDK 21, `ANDROID_HOME` or
`ANDROID_SDK_ROOT`, Android platform 36, build tools 36.0.0, NDK 27.1.12297006, accepted Android SDK
licenses and `unzip`. Supply any additional native compiler components required by the pinned
React Native template in that SDK. Gradle wrappers remain the templates' exact 9.0.0 wrappers;
automatic SDK and Java toolchain downloads are disabled. Missing prerequisites fail before staging
or installing consumers. This command does not provision an Android SDK.

iOS requires macOS, a selected full Xcode installation with the iOS simulator SDK, and an already
installed CocoaPods executable. `xcode-select`, `xcodebuild`, `xcrun` and `pod` must work from the
contributor's tool PATH. The summary records the selected tool versions. No simulator is booted,
no signing identity is requested and no physical device is needed. An inapplicable platform fails;
it is never recorded as a successful skip.

## Commands

Run from the repository root:

```sh
pnpm run smoke:mobile:packed
pnpm run smoke:mobile:android
pnpm run smoke:mobile:ios
```

`packed` builds Core, Interactions and React Native in an isolated staging workspace using the
repository lockfile, then materializes `0.1.0-alpha.16` and release-compatible workspace ranges in
staging only. Source versions stay `0.0.0-development`. It uses **pnpm pack** for those three
packages, including the ordinary license prepack/postpack hooks. `npm pack` is used only to obtain
the two pinned external templates, never to pack a Tileflow workspace package.

Both consumers install local tarball specifications, compile public `Map` usage, compare installed
Tileflow files against the packed files, and verify Android and iOS autolinking. The Expo consumer
uses `expo-template-bare-minimum@55.0.43`, Expo 55.0.31, and Expo's normal native autolinker. It is a
native/bare Expo project, not Expo Go. The Community consumer is generated by CLI 20.2.0 with
`@react-native-community/template@0.83.10`; that template independently pins its installed CLI and
platform packages to **20.0.0**. The smoke checks that distinction rather than borrowing a global CLI.

Both consumers pin React Native 0.83.10, React 19.2.0 and MapLibre React Native 11.3.10. All direct
template dependency ranges are frozen to their declared minimum, with the explicit peer and
TypeScript matrix taking precedence. Fresh npm lockfiles record transitive resolution for that
run; this is not a claim that future registry resolution or native binaries will be byte-identical.

`android` includes all packed checks, then runs each consumer's Gradle wrapper for `assembleRelease`
with Hermes enabled. It requires Release APK metadata and reads the embedded Hermes bundle from
each APK. `ios` includes all packed checks, installs Pods, and builds both Release simulator apps
with code signing disabled. It discovers app outputs from Xcode build settings, not a hard-coded
absolute DerivedData path, and checks each resulting `main.jsbundle` header and length for Hermes
bytecode version 96. Only the documented `$MLRN.post_install(installer)` and
`tileflow_native_admission_post_install(installer)` hooks are added after React Native's existing
iOS post-install hook. No manual Android linking is added.

## Results and cleanup

The final stdout line is one schema-version-1 JSON document. Success identifies the selected
versions, package/template SHA-256 digests, input and consumer lockfile identities, both autolink
results, and any native output identities. Packed-only results explicitly have no native binary
platforms. Neither binary compilation nor a Hermes header is evidence of launch, rendering,
physical-device behavior, Hosted delivery or registry publication.

All staged builds, tools, consumers, tarballs, logs and selected build output directories belong to
one temporary root. HOME, temporary directories and package/native caches are isolated. Commands
have bounded output, network retry settings and per-step deadlines (15 minutes normally, 30 minutes
for Pods and 60 minutes per native build). Cancellation terminates the owned process group before
cleanup. Success is emitted only after cleanup succeeds.

Pass `--keep` deliberately to preserve this root and its bounded command logs for diagnosis:

```sh
pnpm run smoke:mobile:android --keep
```

The diagnostic location is printed on stderr, never used as a durable identity in the result.
Without `--keep`, failure and partial installations are removed too. Cleanup refuses a replaced
root or ownership marker and never recursively deletes a user-supplied destination.

The script unit/contract suite uses injected commands and temporary filesystem fixtures; it does
not install dependencies or invoke native toolchains:

```sh
node --test scripts/mobile-smoke-contract.test.mjs scripts/mobile-smoke-workspace.test.mjs
```
